# 产品需求文档：AI 学习助教 Web 版

## 1. 产品概述

AI 学习助教 Web 版是一款运行在个人电脑上的单用户学习工具。用户可导入视频链接、本地文件或文本，由系统生成学生笔记和教师教纲，并完成出题、答题、批阅、错题分析、薄弱点追踪和复习测验。

Web 化不是简单地把终端菜单搬到浏览器，而是将原系统重构为：

1. 可观察的后台任务系统。
2. 以课程和课时为上下文的学习工作区。
3. 自动保存、失败恢复和清晰反馈的考试体验。
4. 可备份、可迁移、可升级的本地数据系统。

## 2. 目标用户

唯一目标用户是产品拥有者本人：

- 在个人电脑上通过浏览器使用。
- 自己维护 Anthropic API Key。
- 导入自己的学习材料。
- 同时使用学生笔记和教师教纲，不需要角色切换或权限控制。
- 接受 Docker Desktop/Docker Engine 作为运行前置条件。

## 3. 产品目标

### 3.1 核心目标

- 将“导入素材到开始学习”的流程变成可观察、可恢复的后台任务。
- 将笔记、测验、成绩和错题统一到课时上下文中。
- 保留并修正当前系统的自适应出题、AI 批阅和薄弱点闭环。
- 让非开发操作可以在浏览器完成，日常使用不依赖命令行。
- 保持本地优先：业务数据和文件存放在个人电脑，只有必要内容发送给 Claude API。

### 3.2 成功指标

| 指标 | 目标 |
| --- | --- |
| 首次启动 | 按部署文档操作，15 分钟内启动并通过 Claude 连通性测试 |
| 新建课程 | 1 分钟内创建课程并开始导入第一个课时 |
| 任务透明度 | 用户始终能看到当前阶段、进度、开始时间、失败原因和重试操作 |
| 答案可靠性 | 浏览器刷新或异常关闭后，已自动保存答案可恢复 |
| 数据完整性 | 容器重建不丢数据；备份包可在干净环境恢复 |
| 功能对齐 | 当前 CLI 的核心学习闭环在 Web 版中可完成 |

## 4. 核心信息架构

前端开发可以自由决定视觉呈现，但必须保留以下业务入口：

- 学习总览：继续学习、最近任务、掌握度变化、待处理事项。
- 课程：课程列表、课程详情、课时列表和课时工作区。
- 任务中心：导入、生成、批阅、总结、导出任务的统一管理。
- 考试记录：跨课程查看试卷和作答历史。
- 错题与薄弱点：聚合知识弱点、证据、严重度和复习状态。
- 学习进度：课程/课时掌握度和成绩趋势。
- 系统设置：Claude 状态、存储、备份、日志和版本信息。

不设计独立登录页。服务可用时直接进入学习总览；服务未完成初始化时进入首次启动引导。

## 5. 核心用户旅程

### 5.1 首次启动

1. 用户启动 Docker Compose。
2. 浏览器打开 `http://127.0.0.1:8080`。
3. 系统检查数据库迁移、数据卷权限和 Claude secret 是否可读。
4. 若 Claude 未配置，页面展示配置文件路径和验证方式，不允许在前端回显 Key。
5. 用户执行“测试 Claude 连接”。
6. 测试成功后进入学习总览。

验收条件：任何失败必须说明失败组件、可执行修复动作和日志入口，不能只展示“系统错误”。

### 5.2 导入课时

1. 用户选择或创建课程。
2. 新建课时，填写名称和顺序。
3. 选择素材类型：视频 URL、本地上传、粘贴文本。
4. 前端完成基础校验并提交。
5. API 创建课时、素材和导入任务，立即返回任务 ID。
6. Worker 执行下载/读取、提取、清洗、切片、生成、校验和发布。
7. 前端通过 SSE 展示阶段和进度；用户可以离开当前页面。
8. 任务成功后，课时进入 `ready` 状态并可阅读笔记。

任务阶段至少包括：

```text
queued -> acquiring -> detecting -> extracting -> normalizing -> chunking
       -> generating_teacher_outline -> generating_student_notes
       -> validating -> publishing -> succeeded
```

失败任务必须保留已完成阶段、结构化错误和重试入口。重试默认从可安全恢复的最近阶段开始，不能无条件重复下载大文件。

### 5.3 学习课时

1. 用户进入课时工作区。
2. 默认打开学生笔记；可以查看教师教纲、原始文本和内容版本。
3. 系统展示本课掌握度、最近成绩、薄弱点和推荐下一步。
4. 用户可以提交自己的学习总结，后台生成评估。
5. 用户可发起常规测验或复习测验。

验收条件：内容加载失败、内容尚未生成和任务失败必须是三种不同状态，不能统一显示为空页面。

### 5.4 生成测验

1. 用户选择自动题量或手动题量。
2. 后端读取课时内容、历史成绩、最近连续正确/错误和薄弱点。
3. 策略引擎生成题量、认知层次、难度和薄弱点覆盖要求。
4. Worker 调用 Claude Structured Outputs 生成题目。
5. 后端执行 Schema、题型、答案、分值和策略一致性校验。
6. 通过校验的题目进入题库并组成试卷。

复习测验必须是独立业务模式，不能复用常规测验入口却丢失 `retest` 语义。它应优先覆盖未掌握薄弱点，并可混入指定旧课时内容。

### 5.5 答题和批阅

1. 用户开始一次 Attempt，服务端固定当次题目快照。
2. 每次修改答案后自动保存；切题和提交前立即保存。
3. 客观题在提交后由 Go 本地逻辑判分。
4. 全客观题提交后同步进入 `graded`，返回最终结果且不创建批阅 Job；存在主观题时 Attempt 进入 `grading`，API 返回客观题暂定分和非空批阅任务 ID。
5. Worker 批阅主观题并生成逐题反馈、薄弱点和复习建议。
6. 批阅成功后 Attempt 进入 `graded`，前端展示最终成绩。
7. 批阅失败不丢失答案和客观题分；有失败 Job 时可重试 Job，旧数据无 Job 时可从 Attempt 重新发起批阅。

用户提交后答案不可直接编辑。若需要重做，应新建 Attempt，保留历史记录。

### 5.6 错题复习

1. 批阅结果更新薄弱点证据和严重度。
2. 错题页面按课程、课时、知识点、状态聚合。
3. 用户可查看错因、正确理解和关联原笔记。
4. 用户发起复习测验。
5. 连续复测正确时降低严重度；达到条件后标记已掌握。

已掌握薄弱点不删除，保留历史证据和重新激活能力。

## 7. 状态模型

### 7.1 Lesson 状态

| 状态 | 含义 | 可用操作 |
| --- | --- | --- |
| `draft` | 已创建但没有可用内容 | 添加素材、删除 |
| `processing` | 存在活动导入/重生成任务 | 查看进度、取消 |
| `ready` | 已发布有效笔记 | 学习、测验、重生成 |
| `failed` | 最近生成失败且无可用版本 | 查看错误、重试、删除 |
| `ready_with_warning` | 有可用旧版本，但最新重生成失败 | 继续阅读、查看失败、重试 |

### 7.2 Job 状态

`queued -> running -> validating -> succeeded`

终止分支：`failed`、`cancel_requested -> cancelled`。Worker 异常退出且租约过期时，任务回到 `queued` 或进入 `failed`，取决于重试次数和错误类型。

### 7.3 Attempt 状态

`in_progress -> submitted -> grading -> graded`

异常分支：`grading_failed`。它仍然是一份有效的已提交作答，可重试批阅。

## 8. 非功能需求

### 8.1 性能

- 普通列表和详情接口 P95 小于 300ms。
- 首屏不等待任务历史、图表和大 Markdown 全部加载完成。
- 大 Markdown 使用分块渲染或虚拟化策略，避免长文导致交互冻结。
- 单文件默认最大 2GB；限制必须通过配置调整并在上传前展示。
- Worker 默认并发 1，Claude 请求并发与解析并发分别配置。

### 8.2 可靠性

- 所有创建任务的接口必须幂等。
- 同一 Lesson 的素材导入、内容重生成和试卷生成合计最多有一个活动 Job；重复意图返回现有任务，不重复消耗 Claude，也不基于正在变化的内容出题。
- 任务状态变化和结果发布处于数据库事务或可恢复的两阶段发布中。
- 文件写入先写临时路径，校验后原子重命名。
- 容器重启后任务能够通过租约恢复。
- 数据库迁移必须向前兼容当前应用启动过程，并提供升级前备份检查。
- 备份维护模式必须有数据库时间租约和崩溃恢复协议；进程被强杀或主机重启不能永久阻塞写入。

### 8.3 隐私与安全

- 默认仅绑定本机回环地址。
- API 校验 Host 和写请求 Origin，不启用通配 CORS，防止恶意网页借 localhost/DNS rebinding 触发本机操作。
- API Key 只提供给 Worker，禁止写入数据库、日志、浏览器和备份。
- 上传文件名不能直接作为存储路径，必须使用服务端生成 ID。
- 拒绝路径穿越、符号链接逃逸和不受控的本地路径读取。
- URL 下载限制协议、重定向次数、文件大小、超时和内网地址，防止 SSRF。
- Markdown 渲染禁用原始 HTML或经过严格净化。

### 8.4 可观察性

- 每个请求有 `request_id`，每个任务有 `job_id`，每次 Claude 调用有 provider request ID（若 SDK 提供）。
- JSON 日志包含模块、事件、耗时、状态和错误码，不记录 API Key。
- 系统状态页显示服务版本、数据库迁移版本、Worker 心跳、队列长度和存储空间。

## 9. 发布验收

P0 发布前必须演示以下完整链路：

1. 全新环境启动。
2. Claude 连接测试。
3. 导入文本并生成笔记。
4. 导入视频 URL，并展示失败重试或成功流程。
5. 生成试卷、自动保存答案、提交和 AI 批阅。
6. 形成薄弱点并生成复习测验。
7. 重启 API/Worker，验证数据与任务恢复。
8. 执行备份，在干净数据卷恢复。
9. 导入一份旧 Python `course/` 数据。
